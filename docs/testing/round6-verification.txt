Implementation and contract
1. Native GEOMETRY SELECTs retain a typed DuckDB relation. Geometry-aware reads
   alone project ST_AsWKB, using one-based column positions, not names. Ordinary
   SELECTs still return pandas DataFrames. to_pandas fetches native bytes without
   geometry conversion; callers must pass the typed relation directly to
   to_geodataframe. This intentionally replaces round 5's WKB-to-pandas behavior.
   The public docstrings and the engine notebook describe this distinction.
2. Spatial loads only after DuckDB reports a bind dependency on its spatial
   extension, or on an explicitly spatial method. LOAD precedes INSTALL; only a
   missing local extension triggers installation. Failed spatial loads propagate
   and do not prevent later ordinary SQL. SQL batches bind statements separately
   so retrying a spatial bind cannot replay preceding DML.
3. DML uses execute/fetchdf, preserving Count; DDL preserves its empty Count schema.
4. Explicit zero allocation is excluded from distinct-source merge counts and
   intensive numerators/denominators. Invalid contributing areas still reject when
   they cannot be reconstructed. No areal fallback for the legitimate zero case.
5. Census data/year endpoint detection has no dataset-depth assumption. The
   required non-Census-host /data/year/census proxy namespace remains accepted.
A. Redundant slashes and repeated terminal data components normalize to one API
   root component; interior proxy paths are retained.
B. Empty SQL geometry results retain their schema. Empty areal targets now raise
   an explicit ValueError before backend dispatch (the old DuckDB failure was
   pre-existing, not counted as a round-6 regression).
