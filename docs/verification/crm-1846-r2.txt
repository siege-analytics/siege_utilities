B1: capped retry waits

The four constructors expose max_retry_wait=900.0. Wait settings must be finite
and nonnegative. A numeric or HTTP-date Retry-After above the cap raises
ConnectorRateLimitError without sleeping or retrying, with retry_after retained.
Non-finite hints follow the same rule. Thirty seconds sleeps for 30 seconds and
permits a safe-method retry. Exponential fallback waits are capped and cannot
overflow. POST and PATCH transport/server failures remain single-attempt writes.

B2: secret-safe diagnostics

siege_utilities/core/_http.py adds this sibling:
redact_secrets(text: str, *, replacement: str = "[REDACTED]") -> str

It calls redact_url_secrets first. The existing URL redactor is unchanged.
It covers sensitive header pairs, bare Bearer values, form pairs, and quoted
JSON fields. Non-sensitive client_id and normal fields remain visible.
ConnectorError, UpsertError, UpsertResult reprs, and all four connector loggers
use the sibling. Transport diagnostics retain fixed text, exception class and
attempt count. Raw transport exceptions and response decoding errors are not
chained into connector tracebacks. InvalidJSONError has a fresh cause containing
only its class name, preserving the existing typed-cause contract.
Provider error details, including Dynamics inner-batch errors, are redacted
before display or truncation.

The main B2 matrix has 500 cases: four connectors, five payload choices (URL,
header, form, JSON, and all four together), five diagnostic targets, and five
failure paths (transport, encoding, decoding, HTTP rejection and server error).
Every combined payload uses the same sentinel on all four surfaces. Requests
carry query parameters, Authorization and X-Api-Key headers, a prepared form
body, and a JSON body. Assertions cover str(exc), repr(exc), formatted chained
tracebacks, LogRecord.getMessage plus formatted records, and UpsertResult repr.
Transport and server cases assert that log records were emitted; logger capture
is enabled even after Django setup. Twenty provider upsert response cases cover
actual UpsertResult errors, including Dynamics inner batches. Eight token
exchange cases cover transport failures and provider rejections. Twenty-seven
helper cases cover the required sensitive keys and non-sensitive controls.

B3: bulk authentication and result integrity

RefreshOn401 is shared by the four JSON request wrappers and raw CSV/multipart
transfers. Dynamics public upserts renew on an outer or inner changeset 401.
Salesforce CSV upload and success/failure result downloads renew and replay once.
The replay rebuilds authorization headers and Salesforce instance URLs while
retaining request data. Persistent 401 raises ConnectorAuthError. Bulk 429 uses
the B1 wait policy. Result retrieval errors propagate, and incomplete successful
CSV results raise ConnectorError instead of reporting ok=True with empty IDs.
